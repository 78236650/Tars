## 一、项目背景

### 1.1 业务痛点

中远海特（COSCO SHIPPING Specialized）是全球领先的特种船运输公司。风电设备（叶片、塔筒、主机、轮毂）属于超大超重件，配载工作目前依靠**资深工程师经验 + 人工试算**：

- 一船配载图需要工程师反复调整数小时
- 不同船型、不同风电厂家设备差异大，经验难以复用
- 核价测算阶段需要快速出方案，但人工难以满足时效

### 1.2 项目目标

构建"知识沉淀 → 建模求解 → 系统应用 → 持续迭代"四层技术架构：

```
历史配载图(PDF) ──→ 规则萃取 ──→ 规则库 + 知识库
                                    │
                                    ▼
                              智能配载算法(MILP)
                                    │
                                    ▼
                              配载图自动生成(CAD/3D)
                                    │
                                    ▼
                              人工反馈 → 规则增量更新
```

### 1.3 考核指标

| 指标 | 要求 |
|------|------|
| 风电货物种类 | ≥4 类（风叶/塔筒/主机/轮毂） |
| 支持船型 | ≥5 类 |
| 历史案例 | 500 票 |
| 核价方案生成 | ≤30 分钟 |
| 实载方案生成 | ≤1 小时 |
| 专家可采纳率 | ≥80% |
| 约束识别准确率 | ≥85% |
| 安全约束覆盖率 | 100% |
| 场景验证 | ≥100 个项目 |

## 二、配载问题数学建模

### 2.1 问题定义

**目标**：在给定船型上，最大化完整风电套数 S

**货物**：T110.5-70A 风电设备，6 个组件（componentNo 1~6）

**变量**：
- 每个货物 p 的放置决策 yp ∈ {0,1}
- 旁通板 b 的启用决策 zb ∈ {0,1}
- 货物位置 (xp, yp)、层 layer、方向 dir、层数 tier

### 2.2 十大约束条件

| 约束 | 名称 | 核心内容 |
|:---:|------|------|
| C1 | 方向→层数 | dir=0 时 tier=1（横向只能单层） |
| C2 | 成套完整性 | 6 个组件必须全部放置才算 1 套 |
| C3 | Y 轴间隙 | 货物间 y 向间隙 > 100mm |
| C4 | X 轴间隙 | 货物间 x 向间隙 > 500mm |
| C5 | 层 2/3/4 支撑 | 上层货物必须支撑在舱盖/旁通板上 |
| C6 | 遮挡冲突 | 高层货物不能遮挡后方低层货物 |
| C7 | 可行区域+高度 | 在 stowageFeasibleRange 内，满足高度限制 |
| C8 | 旁通板数量 | ≤18 块 |
| C9 | 层 1/2/3 舱口 | 下层货物必须对应 hatch |
| C10 | 甲板强度 | ≤3 t/m² |

### 2.3 求解方法

**MILP（混合整数线性规划）**—— 使用 Pyomo 建模：

```
max S
subject to:
  成套: Σ tier_p·yp ≥ S     ∀ 各组件类型
  间隙: yp1 + yp2 ≤ 1       ∀ 冲突对
  旁通: Σ zb ≤ 18
  强度: Σ ω̃p·yp ≤ σmax·Ab·zb  ∀ 各支撑区域
```

- 候选位置：~5000 个
- MILP 变量：10⁵ ~ 10⁶
- 求解时间：目标 ≤10 分钟，上限 30 分钟
- 验证结果：S* = 27 套（同船型历史最优）

### 2.4 输出产物

| 输出 | 格式 | 用途 |
|------|------|------|
| `result.json` | JSON | 结构化配载数据 |
| `result.dxf` | CAD | 工程配载图 |
| `visual2D.html` | HTML | 二维可视化 |
| `visual3D.html` | HTML | 三维可视化 |

### 3.2 五个 Agent 职责

| Agent | 角色 | 技能 | 知识库 |
|------|------|------|------|
| **规则萃取 Agent** | 从 PDF 配载图 + 规范文档中提取约束规则 | PDF 解析、规则结构化、冲突检测 | 历史配载图纸、船舶规范 |
| **知识管理 Agent** | 维护规则库、船舶库、货物库、历史案例库 | CRUD 操作、规则版本管理、相似案例检索 | 规则库、500 票历史案例 |
| **配载求解 Agent** | 调用 MILP 求解器，生成最优配载方案 | 问题建模、候选生成、求解调度、结果解析 | 船舶参数、约束规则 |
| **方案审核 Agent** | 对生成方案进行安全校核、可采纳性评估 | 约冲突校核、强度校核、视线校核、专家反馈 | 安全标准、历史采纳记录 |
| **可视化 Agent** | 生成 2D/3D 配载图、CAD 文件 | 2D 渲染、3D 渲染、CAD 导出 | 渲染模板 |

### 3.3 全流程演示剧本（6 步）

```
步骤 1: 输入 ── 用户在 PortMeta 对话界面说:
  "请为 T110.5-70A 风电设备在目标船型上配载，目标最大化套数"

步骤 2: 规则检索 ── 知识管理 Agent 自动检索:
  · 该船型的 stowageFeasibleRange
  · 货物参数（尺寸、重量）
  · 约束规则（C1-C10）
  · 历史相似案例 Top 3

步骤 3: 问题建模 ── 配载求解 Agent:
  · 生成候选位置（~5000 个）
  · 构建 MILP 模型（Pyomo）
  · 提交 CBC/GLPK 求解
  · 实时流式返回进度: "正在生成候选位置... 5000/5000"
                          "正在构建 MILP 模型... 变量 85000 个"
                          "正在求解... 迭代中..."
                          "求解完成！最优套数: 27"

步骤 4: 方案审核 ── 审核 Agent:
  · C1-C10 逐条校核 → 全部通过 ✓
  · 相似案例对比 → 匹配度 92%
  · 可采纳评估 → 推荐采纳

步骤 5: 可视化 ── 输出:
  · 内嵌 2D 配载图（Plotly）
  · 3D 配载图链接
  · CAD 文件下载
  · 配载报告（Markdown）

步骤 6: 反馈闭环 ── 专家:
  · "第 3 舱塔筒方向不对，改成纵向"
  · → 规则管理 Agent 记录反馈
  · → 知识库增量更新
  · → 下次求解自动应用新规则
```

## 四、技术实现路径

### 4.1 基于 PortMeta 的 Agent 定义

每个 Agent = 一个 PortMeta 租户 + 技能包 + 知识库：

```
租户: "stowage-solver"
  ├── 知识库: 船舶参数文档 / 约束规则 / 500票历史案例
  ├── 技能包:
  │   ├── solve_stowage(cargo_type, vessel_id) → StowageResult
  │   ├── get_similar_cases(cargo_type, vessel_id) → List[Case]
  │   ├── validate_plan(plan_id) → ValidationReport
  │   └── export_cad(plan_id) → CADFile
  ├── 记忆: 用户偏好（默认船型、常用货物）
  ├── BI 数据源: 历史配载统计
  └── 通道: Web / 企微
```

### 4.2 MCP 工具接口（求解引擎）

```
MCP Server: wind-stowage-solver
  ├── tool: load_vessel_data(vessel_id) → VesselData
  ├── tool: load_cargo_data(cargo_type) → CargoData
  ├── tool: generate_candidates(vessel, cargo) → CandidateList
  ├── tool: build_milp_model(candidates, constraints) → ModelID
  ├── tool: solve_model(model_id) → Solution  (流式进度)
  ├── tool: export_result(solution) → ResultFile
  ├── tool: render_2d(solution) → HTML
  └── tool: render_3d(solution) → HTML
```

### 4.3 分阶段实施

```
Demo 阶段（本周，可演示）:
  └── 单船型 + 单货物类型（T110.5-70A）
      端口：PortMeta 对话界面
      引擎：Python MILP 脚本（简化版 CBC 求解）
      输出：对话中内嵌结果 + JSON 下载

V1 阶段（2 周）:
  └── 集成 Pyomo + 完整 C1-C10 约束
      MCP Server 化
      2D 可视化

V2 阶段（4 周）:
  └── 多船型 + 多货物类型
      规则管理 Agent
      历史案例检索
      3D 可视化

V3 阶段（8 周）:
  └── 规则增量学习闭环
      专家反馈收集
```
