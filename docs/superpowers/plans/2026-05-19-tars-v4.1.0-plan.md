# TARS v4.1.0 "Skill Ecosystem" — 建设方案

## 方案制定日期: 2026-05-19
## 当前版本: v4.0.x
## 目标版本: v4.1.0
## 版本代号: Skill Ecosystem（技能生态）

---

## 一、版本背景与目标

### 1.1 v4.0 回顾

v4.0.0 "Hardened Base" 完成了多用户内网部署的**底座加固**：

- 安全：脱敏、注入防护、审计、记忆权限
- 性能：连接池、Prompt Cache、并发限流、启动优化
- 扩展：Provider 插件化、模块化启动
- 运营：Skill Curator 使用统计、Admin 管理

v4.0 解决了「能不能稳定跑」，但用户反馈 **SkillHub 鸡肋、技能装了不能用、平台能力碎片化**。v4.1 聚焦 **「装了就能用、用了可追踪、生态可扩展」**。

### 1.2 v4.1 核心目标

| 目标 | 说明 | 成功标准 |
|------|------|----------|
| **技能即装即用** | 从 SkillHub 安装到对话生效 ≤ 3 步，无需重启 | 安装后 30 秒内可在对话中触发 |
| **技能智能激活** | SkillRouter 接入主流程，按需注入而非全量堆叠 | Prompt token 增量 ≤ 30%（相比 v4.0 全量注入） |
| **开放生态对接** | 本地 bundled + skills.sh + GitHub 三源统一 | 目录 ≥ 20 个可安装技能，搜索命中率 > 80% |
| **模块闭环** | 会议→知识库、BI→技能、审计→管理台 | 3 条核心流水线可一键完成 |
| **多租户技能隔离** | 按 tenant 隔离技能目录与注册表 | 用户 A 安装的技能对用户 B 不可见 |

### 1.3 产品定位（延续 v4.0）

**通用本地 AI Agent 平台**，内网多用户部署。v4.1 不改变定位，强化 **技能/插件生态** 作为差异化能力。

### 1.4 明确不做（v4.1 范围外）

| 功能 | 决策 | 理由 |
|------|------|------|
| OpenAI-compatible Proxy | ❌ 延至 v4.2 | 非当前用户痛点，复杂度高 |
| 多智能体 Kanban | ❌ 不做 | 子代理 + PDCA 已够用 |
| PyPI 发布 | ❌ 不做 | 内网 git clone / Docker 部署 |
| 全量 Prompt 永久注入 | ❌ 废弃 | 改为 Router + 按需激活，控 token |
| 自建 Skill 商店后端 | ❌ 不做 | 复用 skills.sh + GitHub + 本地 bundled |

## 三、Phase 1 — SkillHub 生态完善

### 3.1 现状与差距

| 项目 | v4.0.x 现状 | v4.1 目标 |
|------|-------------|-----------|
| 技能目录 | 本地 bundled 10 条（已修复假仓库） | + skills.sh 索引，合计 ≥ 20 条 |
| 安装格式 | 支持 SKILL.md + skill.yaml | + 单文件 .md 直装 + tar.gz |
| 安装后体验 | 返回 usage 文本 | 「去试试」跳转 Chat + 预填 prompt |
| 依赖检测 | 仅 Python import 检查 | + CLI 工具（bins）检测 + 安装指引 |
| 重载 | `/api/skills/reload` 空实现 | 真正 reload + 清 cache |

### 3.2 skills.sh 对接方案

- **搜索**：调用 `npx skills find <query> --json`（子进程，超时 15s）或 skills.sh HTTP API（若有）
- **安装**：解析 `owner/repo` 格式，走现有 GitHub tarball 下载 + SKILL.md 识别
- **缓存**：`data/skillhub/skills_sh_index.json`，TTL 24h，减少外网依赖
- **降级**：skills.sh 不可达时仅展示本地 bundled + GitHub topic 搜索

### 3.3 「去试试」闭环

```
ToolsView 安装成功
    → 显示 example_prompt
    → [去试试] 按钮
    → router.push('/chat?prompt=...&skill=pdf')
    → ChatView 读取 query，预填输入框
    → Agent 上下文匹配注入对应技能
```

### 3.4 Plugin 依赖检测

扩展 `skill.yaml` / SKILL.md frontmatter：

```yaml
requires:
  bins: ["gh", "summarize"]      # CLI 工具
  packages: ["pypdf>=4.0"]       # Python 包（已有）
install_hints:
  - "brew install gh"
  - "pip install pypdf"
```

安装前 `which` 检测 bins，缺失则返回 `needs_setup: true` + hints，允许「仍要安装」。

## 四、Phase 2 — 技能激活引擎

### 4.1 问题根因

v4.0 中 `SkillRouter` **已初始化但从未接入** `handle_message`。Agent 仅通过 `get_progressive_disclosure()` 列出技能名，或 v4.0.x 补丁的 keyword 匹配注入——缺少统一的 scene → skill 路由链路。

### 4.2 目标行为

```
用户消息
    → Scene Analyzer（已有，异步）提取 intent/entities/keywords
    → SkillRouter.route() 同步快速版（keyword + intent 规则）
    → Top-K 技能（默认 3）注入 prompt_template
    → 其余技能仅保留 progressive disclosure 一行描述
    → Curator.record_usage(skill_id) 记录激活
```

### 4.3 斜杠命令增强

| 命令 | 行为 |
|------|------|
| `/skill list` | 列出已安装 + 激活状态 |
| `/skill activate <id>` | 强制 sticky 激活（已有，完善反馈） |
| `/skill off` | 关闭当前 sticky |
| `/skill find <query>` | 搜索 SkillHub 并返回 Top 3 推荐 |

### 4.4 Curator 自动归档

- 规则：30 天无调用 + 非 sticky + 非 admin 标记「保留」→ 自动 archive
- 通知：Admin 面板展示「即将归档」列表
- 可配置：`config/skills.yaml` 中 `auto_archive_days: 30`

## 五、Phase 3 — 多租户技能隔离

### 5.1 目录结构

```
skills/
├── _global/              # Admin 安装的全局技能（所有用户可用）
│   └── calculator/
└── tenants/
    └── {tenant_id}/
        └── pdf/          # 用户私有安装
```

### 5.2 加载顺序

1. `_global/` → 注册到 global scope
2. `tenants/{tenant_id}/` → 注册到 tenant scope
3. Agent 构建 prompt 时合并 global + 当前 tenant 技能
4. ToolRegistry：tenant 技能 tool name 加前缀 `{tenant_id}__` 防冲突（可选，P2 简化版可共用 global tool）

### 5.3 API 变更

- `POST /api/skillhub/install` 增加 `scope: global | tenant`（admin 可选 global）
- `GET /api/skills/` 按当前 tenant 过滤

## 六、Phase 4 — 模块流水线闭环

### 6.1 会议 → 知识库

```
Meeting 转写完成
    → 自动生成结构化纪要（已有 meetingSummary utils）
    → [入库知识库] 按钮 / 自动规则
    → knowledge API ingest（collection=meetings, metadata: meeting_id, date）
    → 对话中 knowledge_search 可检索
```

### 6.2 知识库引用溯源

- `knowledge_search` 返回结果带 `doc_id`, `chunk_id`, `source_file`
- ChatPanel 渲染引用卡片：`📄 来源: xxx.pdf (第 3 页)`
- Agent system prompt 要求标注引用

### 6.3 BI 增强

- 数据源 `POST /api/bi/datasources/test` 连接测试
- SQL 执行前 audit log（已有 audit 框架扩展）
- bi_analytics 技能与 BI 模块联动文档

### 6.4 审计台增强

- AuditView 筛选：`action=skill_install | skill_activate | tool_call`
- 关联跳转：skill 事件 → ToolsView 技能详情

## 七、Phase 5 — 平台增强

### 7.1 Provider fallback

```yaml
# config/providers.yaml
fallback_chain:
  - provider: deepseek
    model: deepseek-chat
  - provider: ollama
    model: llama3.2
```

Agent 调用失败（429/5xx/timeout）时按链降级，审计记录 fallback 事件。

### 7.2 记忆增强

- `MemoryScheduler` 增加 `expire_days` 配置
- `GET /api/memory/export?user_id=` JSON 导出
- Admin 面板批量清理过期记忆

### 7.3 交付物

- `docs/01-项目概览/changelog.md` v4.1.0 条目
- `SKILLS_GUIDE.md` 更新（SkillHub 三源、Router、tenant 隔离）
- `docs/04-运维文档/deployment.md` 迁移步骤（v4.0 → v4.1 skills 目录）
- 集成测试套件：`test_skillhub_*`, `test_skill_router_integration`, `test_tenant_skills`

## 九、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| skills.sh CLI 内网不可用 | 无法搜索开放生态 | 本地 bundled 缓存 + GitHub fallback |
| SkillRouter 误激活 | token 膨胀 / 行为偏移 | top_k=3 + min_score 阈值 + 用户 /skill off |
| 多 tenant tool 名冲突 | 调用错误工具 | tenant 前缀或 global 优先策略 |
| 会议入库数据量大 | 向量库膨胀 | 按 collection 配额 + 管理员清理策略 |

## 十、验收标准（Release Checklist）

- [ ] 从 SkillHub 安装 bundled 技能后，对话中 1 条消息内可触发技能行为
- [ ] skills.sh 搜索返回结果并可安装（外网环境）
- [ ] `/skill activate pdf` 后下一轮对话注入 PDF 技能全文
- [ ] 用户 A 安装的技能对用户 B 不可见（tenant 隔离）
- [ ] 会议转写可一键入库并在对话中被 knowledge_search 检索到
- [ ] `/api/skills/reload` 安装新技能后无需重启即可生效
- [ ] 全部单元/集成测试通过，新增测试 ≥ 30 个
- [ ] changelog + SKILLS_GUIDE + 迁移文档更新完毕
