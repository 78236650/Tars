# TARS v4.0.2 — Admin 管理权限 + 角色模板设计

## 版本: v4.0.2
## 日期: 2026-05-18
## 定位: 多租户服务端 — 管理员可配置权限、分配角色模板

---

## 一、背景与目标

### 当前问题

1. **角色固定** — 只有 admin/user/guest 三个硬编码角色，无法自定义
2. **权限不可配置** — `tool_permissions.yaml` 和 `permission.py` 中的权限矩阵是静态的，admin 无法在运行时调整
3. **模块访问无法按用户分配** — modules.yaml 是全局开关，不能按用户/角色控制
4. **缺少管理界面** — admin 无法通过 UI 管理用户权限

### 目标

- Admin 可通过 UI 创建自定义角色模板
- Admin 可为用户分配角色模板
- 角色模板定义：可用工具、可访问模块、资源操作权限
- 提供预置模板（开发者、分析师、访客等）
- 前后端完整实现

## 二、角色模板设计

### 2.1 预置模板

| 模板 ID | 名称 | 工具权限 | 模块访问 | 说明 |
|---------|------|---------|---------|------|
| `admin` | 系统管理员 | 全部 | 全部 | 不可删除/修改 |
| `developer` | 开发者 | 全部工具（含 shell/python_exec） | 全部 | 信任用户，可执行代码 |
| `analyst` | 数据分析师 | web_search, web_fetch, python_exec, file, file_write, knowledge_search, bi | bi, knowledge | 数据分析场景 |
| `operator` | 运维人员 | shell, command, file, file_write, process, network | 全部 | 服务器运维 |
| `standard` | 普通用户 | weather, web_search, web_fetch, file, memory, knowledge_search | knowledge, skillhub | 默认角色 |
| `readonly` | 只读访客 | weather, web_search | 无可选模块 | 最小权限 |

### 2.2 角色模板数据模型

```sql
CREATE TABLE role_templates (
    id TEXT PRIMARY KEY,           -- 模板 ID（如 "developer"）
    name TEXT NOT NULL,            -- 显示名（如 "开发者"）
    description TEXT,              -- 描述
    is_builtin INTEGER DEFAULT 0,  -- 是否预置（预置不可删除）
    allowed_tools TEXT,            -- JSON: ["shell","file",...] 或 "*"
    denied_tools TEXT,             -- JSON: ["process","network"]
    allowed_modules TEXT,          -- JSON: ["bi","knowledge","meeting","skillhub"]
    resource_permissions TEXT,     -- JSON: {"session":["create","read_own"],...}
    workspace_restriction INTEGER DEFAULT 1,  -- 是否限制 workspace
    max_concurrent INTEGER DEFAULT 1,         -- 最大并发 LLM 调用
    created_at TEXT,
    updated_at TEXT
);
```

### 2.3 用户-角色关联

```sql
-- 修改 users 表：role 字段从 enum 改为 role_template_id
ALTER TABLE users ADD COLUMN role_template_id TEXT DEFAULT 'standard';
```

向后兼容：
- `role = "admin"` → `role_template_id = "admin"`
- `role = "user"` → `role_template_id = "standard"`
- `role = "guest"` → `role_template_id = "readonly"`

## 三、后端设计

### 3.1 新建文件

| 文件 | 说明 |
|------|------|
| `backend/tars/gateway/role_template.py` | RoleTemplateManager — CRUD + 权限查询 |
| `backend/tars/api/roles.py` | 角色模板 REST API |
| `backend/tests/test_role_template.py` | 测试 |

### 3.2 RoleTemplateManager

```python
class RoleTemplateManager:
    def __init__(self, db):
        self._db = db
        self._ensure_table()
        self._seed_builtins()

    # CRUD
    def create_template(self, id, name, ...) -> RoleTemplate
    def update_template(self, id, ...) -> bool
    def delete_template(self, id) -> bool  # 预置不可删
    def get_template(self, id) -> RoleTemplate
    def list_templates() -> List[RoleTemplate]

    # 权限查询
    def can_use_tool(self, template_id, tool_name) -> bool
    def can_access_module(self, template_id, module_name) -> bool
    def get_allowed_tools(self, template_id) -> list | "*"
    def get_resource_permissions(self, template_id) -> dict
```

### 3.3 API 端点

```
GET    /api/roles                    — 列出所有角色模板
GET    /api/roles/{id}               — 获取模板详情
POST   /api/roles                    — 创建自定义模板（admin）
PUT    /api/roles/{id}               — 更新模板（admin，预置不可改）
DELETE /api/roles/{id}               — 删除模板（admin，预置不可删）
POST   /api/users/{id}/role          — 为用户分配角色模板（admin）
GET    /api/users/{id}/permissions   — 查看用户有效权限
```

### 3.4 集成改造

| 现有文件 | 改动 |
|---------|------|
| `gateway/permission.py` | `check_permission` 改为从 RoleTemplateManager 查询 |
| `security/tool_permission.py` | `can_use_tool` 改为从 RoleTemplateManager 查询 |
| `modules/registry.py` | 新增 `is_enabled_for_user(module, template_id)` |
| `tools/dispatcher.py` | 工具权限检查走 RoleTemplateManager |
| `database/user_store.py` | 用户表加 `role_template_id` 字段 |
| `api/invoke.py` | request_context 中注入 role_template_id |

## 七、不做的事

- 不做细粒度 ABAC（属性访问控制）— RBAC 模板够用
- 不做角色继承/组合 — 一个用户一个模板，简单明确
- 不做动态权限（按时间/IP 变化）— 内网场景不需要
- 不做审批流程 — admin 直接分配即可
