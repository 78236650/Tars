# TARS v4.0.1 — 多租户 Workspace 隔离

## 版本: v4.0.1
## 日期: 2026-05-18
## 定位: 多租户服务端服务（内网部署，多用户并发）

---

## 一、背景

v4.0.0 完成了安全加固（脱敏/审计/注入防护/记忆权限）、性能优化、Provider 插件化。但文件系统层面所有用户仍共享同一个 workspace 目录，存在隐私风险。

v4.0.1 目标：**补齐文件系统隔离，使 TARS 成为完整的多租户服务端架构。**

## 三、设计

### 3.1 目录结构

```
~/.tars/workspaces/
├── {user_id_1}/
│   ├── files/            # 用户文件读写区
│   └── tmp/              # Shell/Python 临时执行区
├── {user_id_2}/
│   ├── files/
│   └── tmp/
└── _shared/              # 共享文件（所有用户可读，admin 可写）
```

### 3.2 核心组件

**TenantWorkspaceManager** — 管理 per-tenant 目录生命周期：
- `get_workspace(tenant_id)` → 用户文件目录
- `get_tmp_dir(tenant_id)` → 执行临时目录
- `get_allowed_dirs(tenant_id, role)` → 该用户可访问的目录列表
- tenant_id 校验（禁止 `..`、`/`、`\`）

### 3.3 工具隔离策略

| 工具 | 隔离方式 |
|------|---------|
| file (读) | allowed_dirs 限制为 tenant workspace + _shared |
| file_write | sandbox root 设为 tenant workspace |
| shell | cwd 限制为 tenant workspace，环境变量清洗 |
| python_exec | cwd + tmpdir 限制为 tenant workspace |
| file_list | 同 file |

### 3.4 认证加固

- **WebSocket**: 从 query param 提取 api_key，验证 user.id == tenant_id
- **REST API**: X-Tenant-ID 必须匹配认证用户（admin 豁免）
