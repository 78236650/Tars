# TARS Workspace — 右栏折叠与核心弹层统一设计文档

## 概述

本次设计聚焦两个当前已经暴露出来的桌面工作台问题：

- 右侧 Inspector 在桌面态缺少稳定的收起/展开入口，不能形成一致的工作节奏。
- 各页面点击后弹出的详情、编辑、配置界面视觉语言不一致，破坏 `Graphite Amber` 工作台的一体感。

本轮采用“小步统一”的方式：先完善 `DesktopShell` 的桌面态右栏折叠交互，再抽出统一的弹层视觉壳，优先替换高频核心弹层，不在本轮做全项目一次性重构。

**版本：** v2.8.x workspace refinement
**范围：** 前端桌面壳层 + 通用弹层基础组件 + 高频核心弹层替换
**非目标：** 后端 API 变更、页面业务逻辑重写、一次性全量替换所有历史弹层

---

## 1. 目标

### 1.1 用户目标

- 在桌面态始终能看到右栏的收起/展开入口。
- 收起右栏后不丢失上下文，能快速恢复。
- 点击打开的关键弹层在视觉上保持同一套层级、边框、圆角、按钮和关闭方式。

### 1.2 设计目标

- 保持当前 `Graphite Amber` 视觉方向不变，只补齐交互一致性。
- 不把 UI 状态扩散到业务 store，尽量减少对现有页面逻辑的侵入。
- 用通用壳组件统一弹层外观，让后续扩展其他弹层时可以复用。

---

## 2. 右栏折叠设计

### 2.1 状态模型

`DesktopShell` 的右栏分成 3 种状态：

| 状态 | 适用场景 | 行为 |
|------|----------|------|
| expanded | 桌面态默认展开 | 显示完整 320px Inspector |
| collapsed | 桌面态折叠 | 右侧保留 48px 左右窄栏把手 |
| mobile-open | 非 `xl` 视口 | 维持抽屉式打开，不预留固定列 |

说明：

- 桌面态的 `expanded / collapsed` 仅影响 `xl` 及以上视口。
- 非 `xl` 视口仍按现有抽屉逻辑运行，不引入桌面折叠态占位。

### 2.2 布局规则

- `expanded`：主内容区 + 320px Inspector 列。
- `collapsed`：主内容区 + 48px 把手列。
- 把手列固定贴右，保留边框、轻微渐变背景和可点击热区。
- 把手列内容控制为极简信息：
  - `Inspector` 标签
  - 箭头图标
  - 当前页面短标签，如 `Memory`、`Tools`、`Chat`
  - 第一轮短标签固定为 `Chat / Memory / Tools / Shell`，避免折叠态出现过长文案

### 2.3 交互规则

- 点击把手栏，右栏从 `collapsed` 切回 `expanded`。
- 点击完整 Inspector 顶部收起按钮，右栏从 `expanded` 切到 `collapsed`。
- 非 `xl` 视口继续使用“显示右栏 / 关闭”抽屉行为。
- 桌面态切换页面时保留右栏上次状态。
- 状态写入本地存储，仅保存 UI 偏好，不进入业务 store。
- 桌面偏好在 `DesktopShell` 初始化时同步读取，避免页面先展开再折叠的闪动。

### 2.4 路由上下文兼容

- 保留当前 `shellContext` 的按路由生成逻辑。
- 新增一个更短的上下文字段供折叠态使用，例如 `shortLabel`。
- `shortLabel` 由当前路由上下文直接产出，不单独维护第二套路由映射。
- 不重写现有 Inspector 数据结构，避免为折叠态复制一套上下文逻辑。

## 3. 通用弹层设计

### 3.1 组件边界

新增两个基础组件：

```text
AppSurfaceDialog
AppSurfaceDrawer
```

两者只负责“视觉壳”和“通用交互骨架”，不负责业务请求和数据处理。

### 3.2 AppSurfaceDialog

适用场景：

- 居中编辑弹窗
- 删除确认
- 详情查看
- 表单配置

统一职责：

- 遮罩
- 居中容器
- 标题区（标题 + 描述）
- 右上角关闭按钮
- 主体滚动区
- 底部操作区
- 尺寸变体（sm / md / lg / xl）

### 3.3 AppSurfaceDrawer

适用场景：

- 侧边抽屉
- 长内容详情面板
- 多步骤操作流

统一职责：

- 左/右侧滑入面板
- 顶部标题区
- 面板内关闭动作
- 主内容滚动区
- 底部固定操作区

### 3.4 视觉统一规则

- 背景：延续 `Graphite Amber` 深色底。
- 边框：统一 `amber` 低对比描边。
- 圆角：主容器使用大圆角，避免不同弹层一会儿锐利一会儿柔和。
- 阴影：统一为深色大投影，减少当前各组件阴影风格混乱的问题。
- 按钮体系：
  - 主按钮：琥珀实体按钮
  - 次按钮：半透明描边按钮
  - 危险按钮：红色低饱和危险按钮
- 标题区格式统一为：
  - 标题
  - 一行简短说明
  - 明确关闭动作

## 4. 第一批统一范围

本轮只统一高频、用户已经明确感受到割裂的核心弹层：

| 模块 | 优先对象 | 说明 |
|------|----------|------|
| Tools | 工具详情、添加技能 | 与工作台主路径高度相关 |
| Memory | 长期记忆编辑、合并预览、压缩相关弹层 | 已是高频操作区 |
| Knowledge | `KnowledgeManager` 内操作弹层 | 当前风格与工作台脱节 |
| BI | `DataSourceSettings` 配置弹层 | 配置流需要统一壳层 |
| Settings | `UserSettings` 弹层 | 用户感知强、使用频率稳定 |

不纳入本轮：

- 所有低频历史弹层的全量替换
- 每个模块内部的业务交互重构
- 后端接口和数据结构调整

---

## 5. 落地顺序

为减少回归风险，按以下顺序实施：

1. 完成 `DesktopShell` 桌面态右栏折叠
2. 增加右栏折叠相关测试
3. 新增 `AppSurfaceDialog / AppSurfaceDrawer`
4. 先替换 `Tools` 的详情/新增弹层
5. 替换 `Memory` 的长期记忆相关弹层
6. 替换 `KnowledgeManager`
7. 替换 `DataSourceSettings`
8. 替换 `UserSettings`
9. 统一检查主按钮、关闭按钮、标题区和滚动表现

这样做的原因：

- 先把工作台外壳稳定下来，再推进公共弹层。
- 先替换最常用和最显眼的弹层，优先改善真实体验。
- 每一类替换完成后都能单独验证，不需要一次性大面积冒险。

## 6. 数据流与状态管理

### 6.1 右栏状态

- 右栏状态只属于工作台 UI 偏好。
- 状态由 `DesktopShell` 自己管理。
- 使用本地持久化保存，例如：

```text
workspace.inspector.desktop = expanded | collapsed
```

### 6.2 弹层状态

- 业务组件继续持有 `showDialog / showDrawer / editingItem` 等状态。
- 公共弹层组件通过 props + slots 暴露壳层能力。
- 不新增全局 modal store，避免把局部 UI 行为复杂化。

### 6.3 组件职责分离

- 业务组件负责：
  - 请求数据
  - 变更表单
  - 调用 API
  - 业务按钮逻辑
- 公共弹层负责：
  - 布局
  - 外观
  - 关闭行为
  - 动画
  - 滚动区和底部操作区结构

## 7. 测试策略

### 7.1 右栏测试

补充 `DesktopShell` 相关测试，至少覆盖：

- 桌面态可从展开切到折叠
- 折叠态存在窄栏把手且可点击恢复
- 非 `xl` 视口仍走抽屉逻辑
- 路由切换后可保留桌面态折叠状态

### 7.2 通用弹层测试

给 `AppSurfaceDialog / AppSurfaceDrawer` 增加最小交互测试：

- 渲染标题和说明
- 点击关闭按钮触发关闭事件
- footer 操作区渲染正常
- 长内容区域可滚动

### 7.3 手动回归

预览环境中手动检查：

- `Tools`
- `Memory`
- `Knowledge`
- `BI`
- `Settings`

每个模块至少确认：

- 打开
- 关闭
- 主按钮
- 次按钮
- 危险操作区
- 长内容滚动

## 8. 风险与控制

### 8.1 右栏折叠风险

风险：

- 桌面态折叠逻辑和移动抽屉逻辑冲突
- 把手被遮罩或内容层盖住
- 页面切换后状态错乱

控制：

- 折叠态只在 `xl` 及以上视口生效
- 把手单独占列并固定可点击层级
- 折叠状态使用单一键值持久化

### 8.2 通用弹层替换风险

风险：

- 样式统一后原按钮行为失效
- 旧组件 footer/scroll 结构与新壳不匹配
- 某些历史弹层尺寸过窄或过宽

控制：

- 公共弹层先做壳层抽象，不改业务逻辑
- 每接入一类弹层立刻做单点回归
- 提供尺寸变体，避免强制所有弹层一个宽度

---

## 9. 验收标准

- 桌面态右栏可稳定折叠为窄栏，并可通过把手恢复展开。
- 移动端右栏仍然能通过抽屉方式正常打开与关闭。
- 第一批核心弹层在视觉上统一到同一套 `Graphite Amber` 壳层语言。
- 主按钮、次按钮、标题区、关闭动作、滚动区表现一致。
- 单测和构建通过，本地预览可完成核心路径回归。
