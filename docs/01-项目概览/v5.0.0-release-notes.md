# TARS v5.0.0 Release Notes — 多用户协作 + 并发底座

| 项 | 值 |
|----|-----|
| 版本号 | **v5.0.0** |
| 类型 | Platform **major**（架构跃迁） |
| 基于 | v4.4.x 功能基线（港航编排等保留） |
| OpenAPI | `5.0.0`（`backend/tars/main.py`） |
| InsightForge | **INS-2.1.0**（能力版本不变） |
| 设计 SSOT | [2026-05-30-tars-v5.0.0-multiuser-design.md](../superpowers/plans/2026-05-30-tars-v5.0.0-multiuser-design.md) |

## 摘要

v5.0.0 将产品定位从「伪多租户（每用户一岛）」调整为 **单港航企业 · 多用户协作 · 组织共享池**：

1. **身份** — 账号密码 + **JWT**（人类用户）；API Key 保留机器集成
2. **组织池** — `org_default` 下共享记忆(shared)、知识库、实体图谱；会话 / private 记忆 / core_memory 按 `user_id` 隔离
3. **并发底座** — 主库支持 **PostgreSQL**（`DATABASE_URL`）；生产部署 **单 uvicorn worker**（方案 A）

**明确不做（本版）：** SaaS 多企业隔离、声明式 workflow（G3）、港航 Agent 真工具实化（V1）→ **v5.1+**。

---

## Phase 1 — 身份与上下文

| 能力 | 说明 |
|------|------|
| `ORG_ID` | 常量 `org_default`；废弃 `user_id == tenant_id` |
| JWT | `gateway/jwt_auth.py`；`auth_tokens` 表（jti 吊销） |
| Principal | `api/_auth.py`：Bearer 或 `X-API-Key`；`X-Tenant-Id` 不再用于 impersonate |
| 请求上下文 | `context.py` + `UserContextMiddleware` |
| 前端 | `access_token` + `Authorization: Bearer`；WebSocket `?token=` |

---

## Phase 2 — 组织池数据模型

| 能力 | 说明 |
|------|------|
| 记忆 | `memories.user_id`；过滤 `org_default AND (shared OR user_id=?)` |
| Chroma | 集合 `memories_org_default`；metadata `scope` / `user_id` |
| 知识库 | `document_collections` 统一 org；API 用 contextvars，移除 `x_tenant_id` 双轨 |
| 会话 | `session_repo` 按 `user_id` + `ORG_ID` |
| core_memory | `core_memory_blocks` 按用户 `(tenant_id, user_id, name)` |
| 实体图谱 | 全局共享（仅补测试） |

**迁移脚本（SQLite 现网）：**

```bash
cd backend
python3 scripts/migrate_memories_v5_org.py
python3 scripts/migrate_knowledge_v5_org.py
python3 scripts/migrate_chroma_memories_v5_org.py   # 有向量库时
```

## Phase 3 — Postgres 并发底座

| 能力 | 说明 |
|------|------|
| 驱动 | `database/driver.py`：`DbConnection` / `?`→`%s`；连接池 |
| Schema | `connection_pg.py`（无 SQLite FTS5 虚表） |
| 检索 | PG：`to_tsvector` + `ILIKE` 兜底 |
| 迁移 | `scripts/migrate_sqlite_to_pg.py`（`--dry-run`） |
| 部署 | `deploy/docker-compose.yml` 含 **postgres:16**；`workers=1` |

**环境变量：**

| 变量 | 说明 |
|------|------|
| `DATABASE_URL` | `postgresql://user:pass@host:5432/tars`（生产）；不设则 SQLite `data/tars.db` |
| `TARS_JWT_SECRET` | JWT 签名密钥（生产必填，建议 ≥32 字节） |
| `TARS_PG_POOL_MAX` | Postgres 连接池上限（默认 10） |

---

## 破坏性变更（升级必读）

| 变更 | 影响 |
|------|------|
| `Principal.tenant_id` | 恒为 `org_default`（组织作用域），不再是 `user.id` |
| 登录响应 | 增加 `data.access_token`；前端默认 Bearer |
| 知识库 API | 不再以 `X-Tenant-Id` 选库；需登录 JWT |
| 会话列表 API | 需认证；仅返回当前用户会话 |
| 多 worker | v5.0 **不支持** `--workers > 1`（审批/handoff 在进程内）；v5.1+ 再做 T3.5 |

---

## 验收场景

1. 用户 A、B 各自 JWT 登录，private 会话/记忆互不可见。
2. A 写入 **shared** 记忆或知识库文档，B 可检索/召回。
3. `DATABASE_URL` 指向 Postgres 时并发写无 `database is locked`。
4. Docker Compose 一键起：`cd deploy && docker compose up -d --build`。
