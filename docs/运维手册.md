## 1. 系统概述

### 1.1 系统架构

TARS 采用五层架构设计，各层职责明确，协同工作：

```
┌─────────────────────────────────────────────────────────────────┐
│ 第一层：通道层（Channels）                                       │
│   支持 WebSocket 实时通信和 REST API 调用                        │
├─────────────────────────────────────────────────────────────────┤
│ 第二层：网关层（Gateway）                                         │
│   身份核验 / 速率限制 / 安全策略 / Session 路由 / 权限检查        │
├─────────────────────────────────────────────────────────────────┤
│ 第三层：智能体层（Agent）                                         │
│   Agent Loop / 工作区 / 记忆系统 V3 / 子代理 / 工具调度           │
├─────────────────────────────────────────────────────────────────┤
│ 第四层：模型层（Model）                                           │
│   Provider 插件架构（Ollama / OpenAI Compatible）               │
├─────────────────────────────────────────────────────────────────┤
│ 第五层：执行层（Execution）                                       │
│   工具 / 技能 / 文件 / Shell / Python / Cronjob / Memory         │
└─────────────────────────────────────────────────────────────────┘
```

该架构参考了 OpenClaw 的五层架构和 Hermes 的工具注册表设计理念，结合 Letta 的记忆系统，形成了一套完整的多租户 AI Agent 解决方案。

### 1.2 核心模块

| 模块名称 | 功能说明 | 代码位置 |
|----------|----------|----------|
| Agent | 消息处理、工具调度、记忆管理、反思器调用 | `backend/tars/agent/` |
| Tools | 14 个内置工具（weather、file、shell 等） | `backend/tars/tools/` |
| Memory | 三层记忆系统（Core + Archival + Reflector） | `backend/tars/memory/` |
| Skills | 技能系统、SkillHub 市场、技能统计 | `backend/tars/skills/` |
| Security | 脱敏引擎、注入防护、审计日志、权限检查 | `backend/tars/security/` |
| Models | LLM Provider 插件管理、热切换支持 | `backend/tars/models/` |
| Database | SQLite 数据层、FTS5 全文检索 | `backend/tars/database/` |
| Modules | 可选模块管理（BI、会议、知识库） | `backend/tars/modules/` |

### 1.3 数据存储架构

| 数据类型 | 存储方式 | 存储路径 |
|----------|----------|----------|
| 主数据库 | SQLite | `~/.tars/data/tars.db` |
| 审计日志 | SQLite | `~/.tars/data/audit.db` |
| 用户工作区 | 文件系统 | `~/.tars/workspaces/{user_id}/` |
| 上传文件 | 文件系统 | `~/.tars/uploads/` |
| 向量索引 | ChromaDB | `~/.tars/vector_db/chroma/` |
| 临时文件 | 文件系统 | `~/.tars/workspaces/{user_id}/tmp/` |

## 3. 安装部署

### 3.1 获取源代码

通过 Git 克隆代码仓库：

```bash
git clone <repository-url>
cd TARS
```

建议使用稳定版本分支以获得更好的稳定性：

```bash
git checkout v4.0.2
```

### 3.2 后端安装

#### 3.2.1 创建 Python 虚拟环境

使用虚拟环境隔离项目依赖，避免与系统 Python 冲突：

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate  # Linux/macOS
# .venv\Scripts\activate   # Windows PowerShell
# .venv\Scripts\activate.bat  # Windows CMD
```

#### 3.2.2 安装核心依赖

```bash
pip install -r requirements.txt
```

#### 3.2.3 安装可选依赖

根据需要安装额外的功能依赖：

```bash
# BI 数据分析支持
pip install pandas openpyxl

# 图片处理支持
pip install Pillow

# 向量嵌入支持（记忆语义检索）
pip install sentence-transformers
```

#### 3.2.4 配置环境变量

复制环境变量模板文件并编辑：

```bash
cp .env.example .env
vim .env
```

配置示例：

```bash
# LLM API Keys（根据使用的服务商选择配置）
DEEPSEEK_API_KEY=sk-your-deepseek-key
DASHSCOPE_API_KEY=sk-your-dashscope-key
OPENROUTER_API_KEY=sk-or-your-openrouter-key

# Ollama 配置（默认本地模型）
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen3:8b

# 超时配置（秒）
TARS_LLM_READ_TIMEOUT=600
TARS_LLM_CONNECT_TIMEOUT=30

# 日志级别
LOG_LEVEL=INFO
```

### 3.3 前端安装

```bash
cd ../frontend
npm install
```

如果网络较慢，可以使用国内镜像：

```bash
npm install --registry=https://registry.npmmirror.com
```

### 3.4 YAML 配置文件

在 `backend/config/` 目录下创建和编辑配置文件：

#### 3.4.1 providers.yaml — LLM Provider 配置

定义可用的模型提供商：

```yaml
default_provider: ollama-local

providers:
  ollama-local:
    type: ollama
    base_url: http://localhost:11434
    default_model: qwen3:8b
    display_name: Ollama (本地)

  deepseek:
    type: openai_compat
    base_url: https://api.deepseek.com/v1
    api_key: "${DEEPSEEK_API_KEY}"
    default_model: deepseek-chat
    display_name: DeepSeek

  dashscope:
    type: openai_compat
    base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
    api_key: "${DASHSCOPE_API_KEY}"
    default_model: qwen-plus
    display_name: 通义千问
```

**环境变量引用**：使用 `${VAR_NAME}` 语法，启动时自动从环境变量展开。

#### 3.4.2 modules.yaml — 模块启用控制

控制可选模块的加载状态：

```yaml
modules:
  core:
    - agent
    - tools
    - skills
    - memory
    - auth
    - security

  optional:
    meeting:
      enabled: false
      description: 会议助手（需要 whisper 模型）
    bi:
      enabled: false
      description: BI 数据分析（需要 pandas） 
    knowledge:
      enabled: true
      description: 知识库与向量检索
    skillhub:
      enabled: true
      description: 技能市场
```

**配置说明**：禁用的模块不会注册相关路由，也不加载对应依赖，可以有效减少启动时间和内存占用。

#### 3.4.3 concurrency.yaml — 并发限流配置

控制 LLM 调用并发数：

```yaml
providers:
  ollama:
    max_concurrent: 2       # 全局最大并发调用数
    per_user_max: 1         # 单用户最多占用的并发槽位
    queue_timeout: 60       # 排队等待超时时间（秒）
  openai_compat:
    max_concurrent: 5
    per_user_max: 2
    queue_timeout: 30
```

#### 3.4.4 tool_permissions.yaml — 工具权限配置

定义各角色的工具使用权限：

```yaml
roles:
  admin:
    allowed_tools: "*"
    workspace_restriction: false
  user:
    allowed_tools:
      - weather
      - web_search
      - web_fetch
      - file
      - file_write
      - python_exec
      - memory
      - command
      - knowledge_search
    denied_tools:
      - shell
      - process
      - network
    workspace_restriction: true
  guest:
    allowed_tools:
      - weather
      - web_search
    workspace_restriction: true
```

### 3.5 Docker 部署

#### 3.5.1 docker-compose.yml 配置

创建 `docker-compose.yml` 文件：

```yaml
version: "3.8"

services:
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    volumes:
      - ./backend/config:/app/config
      - tars-data:/app/data
      - tars-workspaces:/app/workspaces
    env_file:
      - ./backend/.env
    environment:
      - TARS_DATA_DIR=/app/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
    ports:
      - "5173:80"
    depends_on:
      - backend
    restart: unless-stopped

volumes:
  tars-data:
  tars-workspaces:
```

#### 3.5.2 构建和启动

```bash
# 构建镜像
docker-compose build

# 后台启动服务
docker-compose up -d

# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f
```

#### 3.5.3 Nginx 反向代理配置

如需通过域名访问，配置 Nginx 反向代理：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://localhost:5173;
        proxy_set_header Host $host;
    }

    location /api {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
    }

    location /ws {
        proxy_pass http://localhost:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```

## 4. 配置管理

### 4.1 配置优先级

TARS 的配置按以下优先级生效（高优先级覆盖低优先级）：

| 优先级 | 配置来源 | 说明 |
|--------|----------|------|
| 1（最高） | 环境变量 | `~/.tars/.env` 或系统环境变量 |
| 2 | 命令行参数 | `uvicorn --host 0.0.0.0` |
| 3 | YAML 配置文件 | `backend/config/*.yaml` |
| 4（最低） | 代码默认值 | 各模块的默认参数 |

### 4.2 主要配置项详解

#### 4.2.1 数据目录配置

```bash
# 配置数据存放目录
export TARS_DATA_DIR=/opt/tars/data
```

默认情况下，数据存放在 `~/.tars/` 目录下，包括数据库、工作区、向量索引等。

#### 4.2.2 服务端口配置

```bash
export TARS_HOST=0.0.0.0  # 监听地址
export TARS_PORT=8000       # 后端端口
```

#### 4.2.3 LLM 相关配置

```bash
# Ollama 配置
export OLLAMA_BASE_URL=http://localhost:11434
export OLLAMA_MODEL=qwen3:8b

# API 调用超时（秒）
export TARS_LLM_READ_TIMEOUT=600
export TARS_LLM_CONNECT_TIMEOUT=30
```

#### 4.2.4 安全配置

```bash
# 审计日志开关
export TARS_AUDIT_ENABLED=true

# 脱敏模式：partial（保留部分信息）/ redact（完全替换）
export TARS_SANITIZER_MODE=partial

# 注入防护阈值：high / medium / low
export TARS_INJECTION_THRESHOLD=high
```

#### 4.2.5 日志配置

```bash
# 日志级别：DEBUG / INFO / WARNING / ERROR
export LOG_LEVEL=INFO

# 日志文件路径（可选）
export LOG_FILE=/var/log/tars/app.log
```

### 4.3 运行时配置修改

#### 4.3.1 模块开关调整

修改 `modules.yaml` 后需要重启后端服务使配置生效：

```bash
# 编辑配置
vim backend/config/modules.yaml

# 重启服务（systemd）
systemctl restart tars-backend

# 或 Docker 环境
docker-compose restart backend
```

#### 4.3.2 Provider 热切换

v4.0.0+ 支持通过 API 动态切换 Provider，无需重启服务：

```bash
# 查看所有可用 Provider
curl http://localhost:8000/api/providers

# 测试 Provider 连接状态
curl -X POST http://localhost:8000/api/providers/deepseek/test \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-chat"}'

# 切换默认 Provider（需要 admin 权限）
curl -X POST http://localhost:8000/api/providers/deepseek/switch
```

#### 4.3.3 角色模板动态管理

v4.0.2 新增通过 API 管理角色模板：

```bash
# 查看所有角色模板
curl http://localhost:8000/api/roles -H "X-User-Role: admin"

# 创建自定义角色模板
curl -X POST http://localhost:8000/api/roles \
  -H "X-User-Role: admin" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "custom_analyst",
    "name": "高级分析师",
    "description": "BI + Python + 知识库",
    "allowed_tools": ["web_search", "web_fetch", "python_exec", "file", "file_write", "knowledge_search"],
    "allowed_modules": ["bi", "knowledge"],
    "max_concurrent": 2
  }'

# 为用户分配角色
curl -X POST http://localhost:8000/api/users/user123/role \
  -H "X-User-Role: admin" \
  -H "Content-Type: application/json" \
  -d '{"role_template_id": "custom_analyst"}'
```

### 4.4 配置验证

修改配置后，建议验证配置文件的语法正确性：

```bash

python3 -c "import yaml; yaml.safe_load(open('config/providers.yaml'))"
```

## 5. 启动与停止

### 5.1 开发环境启动

#### 5.1.1 启动后端服务

```bash
cd backend
source .venv/bin/activate

# 开发模式（支持热重载）
.venv/bin/python -m uvicorn tars.main:app --host 0.0.0.0 --port 8000 --reload

# 或指定日志文件
.venv/bin/python -m uvicorn tars.main:app \
  --host 0.0.0.0 --port 8000 --reload \
  --log-config logging.json
```

#### 5.1.2 启动前端服务

```bash
cd frontend

# 开发模式
npm run dev

# 前端会在 http://localhost:5173 提供服务
```

#### 5.1.3 验证服务状态

```bash
# 检查后端健康状态
curl http://localhost:8000/api/health

# 检查模块状态
curl http://localhost:8000/api/modules | python3 -m json.tool
```

### 5.2 生产环境启动

#### 5.2.1 systemd 服务配置

创建后端服务文件 `/etc/systemd/system/tars-backend.service`：

```ini
[Unit]
Description=TARS Backend Service
Documentation=https://github.com/your-repo/TARS
After=network.target

[Service]
Type=simple
User=tars
Group=tars
WorkingDirectory=/opt/tars/backend
Environment="PATH=/opt/tars/backend/.venv/bin"
Environment="TARS_DATA_DIR=/opt/tars/data"
ExecStart=/opt/tars/backend/.venv/bin/python -m uvicorn tars.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

创建前端服务文件 `/etc/systemd/system/tars-frontend.service`：

```ini
[Unit]
Description=TARS Frontend Service
Documentation=https://github.com/your-repo/TARS
After=network.target

[Service]
Type=simple
User=tars
Group=tars
WorkingDirectory=/opt/tars/frontend
ExecStart=/opt/tars/frontend/.venv/bin/npm run preview -- --host 0.0.0.0 --port 5173
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

#### 5.2.2 安装和启动服务

```bash
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 设置开机自启
sudo systemctl enable tars-backend tars-frontend

# 启动服务
sudo systemctl start tars-backend tars-frontend

# 查看服务状态
sudo systemctl status tars-backend
sudo systemctl status tars-frontend
```

#### 5.2.3 后台运行模式（nohup）

如果不想使用 systemd，可以使用 nohup 后台运行：

```bash
# 创建日志目录
sudo mkdir -p /var/log/tars

# 后端后台运行
cd /opt/tars/backend
sudo nohup .venv/bin/python -m uvicorn tars.main:app \
  --host 0.0.0.0 --port 8000 \
  > /var/log/tars/backend.log 2>&1 &

# 前端构建后后台运行
cd /opt/tars/frontend
sudo npm run build
sudo nohup npm run preview -- --host 0.0.0.0 --port 5173 \
  > /var/log/tars/frontend.log 2>&1 &

# 查看进程
ps aux | grep tars
```

### 7.1 备份策略概述

#### 7.1.1 备份内容清单

| 备份内容 | 存储路径 | 备份频率 | 保留周期 |
|----------|----------|----------|----------|
| 主数据库 | `~/.tars/data/tars.db` | 每日 | 30 天 |
| 审计日志 | `~/.tars/data/audit.db` | 每日 | 30 天 |

| 向量索引 | `~/.tars/vector_db/` | 每周 | 14 天 |
| 上传文件 | `~/.tars/uploads/` | 每周 | 14 天 |
| YAML 配置文件 | `backend/config/` | 每次修改后 | 6 个月 |

#### 7.1.2 备份存储建议

| 存储位置 | 优点 | 缺点 |
|----------|------|------|
| 本地磁盘 | 恢复速度快 | 可能与服务器一同损坏 |
| 网络存储（NFS） | 集中管理 | 需要网络连接 |
| 对象存储（OSS/S3） | 可靠性高 | 恢复较慢 |
| 混合策略 | 安全可靠 | 配置复杂 |

### 7.2 备份脚本

创建自动化备份脚本 `/opt/tars/scripts/backup.sh`：

```bash
#!/bin/bash
set -e

# 配置
BACKUP_DIR="/opt/tars/backups"
DATE=$(date +%Y%m%d_%H%M%S)
TARS_HOME="$HOME/.tars"
BACKUP_USER="tars"
LOG_FILE="/var/log/tars/backup.log"

# 创建备份目录
mkdir -p "$BACKUP_DIR"

# 日志函数
log() {
    echo "[$DATE] $1" | tee -a "$LOG_FILE"
}

log "开始执行备份..."

# 备份数据库
if [ -f "$TARS_HOME/data/tars.db" ]; then
    tar -czf "$BACKUP_DIR/tars-data-$DATE.tar.gz" \
        -C "$TARS_HOME" data/ 2>/dev/null
    log "数据库备份完成: tars-data-$DATE.tar.gz"
else
    log "警告: 数据库文件不存在"
fi

# 备份工作区（可选，较大）
if [ "$1" == "--with-workspaces" ]; then
    tar -czf "$BACKUP_DIR/tars-workspaces-$DATE.tar.gz" \
        -C "$TARS_HOME" workspaces/ 2>/dev/null
    log "工作区备份完成: tars-workspaces-$DATE.tar.gz"
fi

# 备份向量索引（可选）
if [ "$1" == "--with-vectors" ]; then
    tar -czf "$BACKUP_DIR/tars-vector-$DATE.tar.gz" \
        -C "$TARS_HOME" vector_db/ 2>/dev/null
    log "向量索引备份完成: tars-vector-$DATE.tar.gz"
fi

# 清理过期备份（保留 30 天）
find "$BACKUP_DIR" -name "*.tar.gz" -mtime +30 -delete
log "过期备份清理完成"

# 设置权限
chown -R "$BACKUP_USER:$BACKUP_USER" "$BACKUP_DIR"

# 显示备份文件列表
log "备份完成，当前备份文件:"
ls -lh "$BACKUP_DIR" | tail -10

log "备份任务执行完毕"
```

添加执行权限并配置定时任务：

```bash
# 添加执行权限
chmod +x /opt/tars/scripts/backup.sh

# 编辑 crontab
crontab -e

# 添加定时任务（每日凌晨 3 点执行）
0 3 * * * /opt/tars/scripts/backup.sh >> /var/log/tars-backup.log 2>&1

# 每周日凌晨 4 点执行完整备份（含工作区和向量索引）
0 4 * * 0 /opt/tars/scripts/backup.sh --with-workspaces --with-vectors >> /var/log/tars-backup.log 2>&1
```

### 8.5 自动化监控脚本

创建监控脚本 `/opt/tars/scripts/monitor.sh`：

```bash
#!/bin/bash

ALERT_WEBHOOK="${ALERT_WEBHOOK:-}"  # 设置告警 webhook URL
ALERT_EMAIL="${ALERT_EMAIL:-}"       # 设置告警邮箱

# 发送告警函数
send_alert() {
    local message="$1"
    echo "[ALERT] $message"
    
    if [ -n "$ALERT_WEBHOOK" ]; then
        curl -X POST "$ALERT_WEBHOOK" \
            -H "Content-Type: application/json" \
            -d "{\"text\": \"TARS Alert: $message\"}" 2>/dev/null
    fi
}

# 1. 检查服务状态
if ! lsof -i :8000 > /dev/null 2>&1; then
    send_alert "Backend service is DOWN"
fi

# 2. 检查磁盘空间
USAGE=$(df ~/.tars 2>/dev/null | tail -1 | awk '{print $5}' | sed 's/%//')
if [ -n "$USAGE" ] && [ "$USAGE" -gt 90 ]; then
    send_alert "Disk usage is above 90%: ${USAGE}%"
fi

# 3. 检查内存使用
MEM=$(ps aux | grep uvicorn | grep -v grep | awk '{sum+=$6} END {print int(sum/1024)}')
if [ -n "$MEM" ] && [ "$MEM" -gt 4096 ]; then
    send_alert "Memory usage is above 4GB: ${MEM}MB"
fi

# 4. 检查 API 响应
if ! curl -sf http://localhost:8000/api/health > /dev/null; then
    send_alert "API health check failed"
fi

# 5. 检查错误日志
ERROR_COUNT=$(journalctl -u tars-backend --since "5 minutes ago" -p err 2>/dev/null | wc -l)
if [ "$ERROR_COUNT" -gt 10 ]; then
    send_alert "High error count in recent logs: $ERROR_COUNT"
fi

# 6. 检查备份执行情况
LAST_BACKUP=$(ls -t /opt/tars/backups/tars-data-*.tar.gz 2>/dev/null | head -1)
if [ -n "$LAST_BACKUP" ]; then
    BACKUP_AGE=$(find "$LAST_BACKUP" -mtime +1 | wc -l)
    if [ "$BACKUP_AGE" -gt 0 ]; then
        send_alert "Latest backup is older than 24 hours"
    fi
fi
```

```bash

*/5 * * * * /opt/tars/scripts/monitor.sh >> /var/log/tars-monitor.log 2>&1
```

## 10. 故障排除

### 10.1 常见问题诊断

#### 10.1.1 后端启动失败

**问题表现**：执行启动命令后报错，服务无法启动。

**诊断步骤**：

```bash
# 1. 检查依赖是否完整
cd backend
source .venv/bin/activate
python -c "import fastapi, uvicorn, sqlalchemy; print('依赖检查通过')"

# 2. 检查配置文件语法
python -c "import yaml; yaml.safe_load(open('config/providers.yaml'))"

# 3. 检查端口占用
lsof -i :8000

# 4. 查看详细错误日志
.venv/bin/python -m uvicorn tars.main:app --host 0.0.0.0 --port 8000 --reload
```

**常见原因和解决方案**：

| 原因 | 解决方案 |
|------|----------|
| 依赖未安装 | `pip install -r requirements.txt` |
| 端口被占用 | `kill $(lsof -ti :8000)` 或使用其他端口 |
| 配置文件错误 | 检查 YAML 语法，确保格式正确 |
| 权限不足 | `chmod +x` 或使用 sudo |
| Python 版本不对 | 确认 Python 版本 >= 3.11 |

#### 10.1.2 前端启动失败

```bash
# 1. 删除 node_modules 重新安装
cd frontend
rm -rf node_modules package-lock.json
npm install

# 2. 检查 Node.js 版本
node -v  # 确保 >= 18

# 3. 查看构建错误
npm run build
```

#### 10.1.3 工具调用失败

**问题表现**：聊天中使用工具时报错。

```bash
# 1. 检查工具注册状态
```

**常见问题**：

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 工具权限不足 | 用户角色未授权 | 修改 tool_permissions.yaml |
| Shell 命令被拦截 | 危险命令黑名单 | 检查 shell.py 配置 |
