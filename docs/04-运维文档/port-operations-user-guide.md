# 港口作业调度 · 用户指南

> 适用版本：**TARS v4.4.0+**  
> 面向：码头调度、堆场值班、船务等业务人员（无需了解 Agent / API 等技术术语）

## 1. 功能是什么

**作业调度**帮你在一个页面里发起港口协同作业：系统自动调用 **泊位调度**、**船务确认**、**堆场分配** 三位「专家」，把各自的处理意见汇总给你看。

典型场景：

- 船舶到港，需要安排靠泊并卸货
- 为到港船舶分配堆场箱位
- 确认船舶 ETA、航次与吃水

## 2. 如何进入

1. 登录 TARS
2. 左侧导航点击 **「作业调度」**
3. 或直接打开：`/orchestration`（例如 `http://localhost:5173/orchestration`）

若看不到菜单，请联系管理员：你的角色需开通 **作业调度** 模块权限。

## 3. 两种 Tab

| Tab | 用途 |
|-----|------|
| **协同作业** | 快捷场景 / 引导填写 / 自由描述，触发泊位·船务·堆场专家 |
| **进出港计划** | 48 小时泊位甘特图、平面泊位图、优化与下发 |

### 进出港计划（v4.5）

1. 切换到 **「进出港计划」** Tab
2. 点击 **重新优化** — 系统用拟真船期自动生成泊位安排
3. 查看 **泊位甘特图**（色块=作业，虚线=等待）与 **泊位平面图**
4. 点击船舶行打开 **详情抽屉**，可改泊位、锁定计划
5. 勾选船舶 → **确认下发** — 自动切回协同作业并打开任务详情

## 4. 三种操作方式（协同作业 Tab）

| 方式 | 适合谁 | 怎么用 |
|------|--------|--------|
| **快捷场景**（默认） | 一线值班 | 点场景卡片（靠泊卸货 / 堆场分配 / 船务确认）→ 填船名或航次 → 发起 |
| **引导填写** | 需要填完整信息 | 按表单填船舶、箱量、泊位、ETA、作业类型 → 提交 |
| **自由描述** | 熟手调度员 | 用一句话描述需求，例如：「安排 COSCO123 明天靠 3 号泊位卸 800 箱」 |

页面上方有 **三步进度**：选择场景 → 填写信息 → 查看结果。

## 5. 查看结果

- **右侧「最近作业」**：历史记录列表，点一条打开详情
- **详情抽屉**：
  - **专家处理结果**：泊位 / 船务 / 堆场各自的意见卡片
  - **协同摘要**：用人话汇总（技术人员可展开「原始数据」）
  - **冲突告警**：若同一泊位时间窗冲突，会黄色提示

## 6. 参与协同的三位专家

| 显示名称 | 做什么 |
|----------|--------|
| 泊位调度 | 安排靠泊窗口、水深与泊位 |
| 船务确认 | 核对 ETA、航次、吃水 |
| 堆场分配 | 规划箱位与堆存 |

一次作业可能同时调用多位专家，无需手动分别操作。

## 7. 角色与权限

| 角色 | 作业调度菜单 | 说明 |
|------|--------------|------|
| 普通用户 `standard` | ✅ | 默认业务用户 |
| 业务分析师 `business_analyst` | ✅ | 问数 + 作业 |
| 开发者 / 运维 | ✅ | 含完整模块 |
| 鉴数分析师 `insight_analyst` | ❌ | 仅鉴数，不含调度 |
| 只读访客 `readonly` | ❌ | 最小权限 |

管理员在 **系统管理 → 角色模板** 中勾选 **「作业调度」** 可为自定义角色开通。

## 8. 部署与运维注意

- 后端 `backend/config/modules.yaml` 中 `orchestration.enabled` 须为 `true`，修改后**重启后端**
- 前端更新菜单文案后，用户需 **刷新浏览器** 或 **重新登录** 以加载最新权限
- 当前 MVP 为 **模拟决策**（非真实 TOS/EDI 回写）；生产对接需 v4.5+ 集成项

## 9. 常见问题

**Q：菜单里没有「作业调度」？**  
A：确认模块已启用、角色含 `orchestration` 权限，刷新或重新登录。

**Q：提交后没有结果？**  
A：查看详情抽屉；若状态为「进行中」请稍候刷新。后端未启动时列表会加载失败。

**Q：和聊天有什么区别？**  
A：聊天是通用对话；作业调度是结构化港口协同，结果按专家分卡片展示，便于值班查阅。
