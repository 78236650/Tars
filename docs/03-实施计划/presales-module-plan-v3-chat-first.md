# TARS 售前管理模块 — 重新设计方案（v3.0 Chat-First）

> 版本：v3.0 | 日期：2026-06-02 | 状态：重新规划

---

## 零、v2.0 的问题

v2.0 方案的核心缺陷：

| 问题 | 说明 |
|------|------|
| **与 Chat 脱节** | 售前功能做成独立 Tab 页，和 TARS 核心的对话能力完全割裂 |
| **重复建设** | 资料库 = 知识库 + Wiki，这两个 TARS 已有，不需要再包一层 |
| **用户心智负担** | 售前经理需要在多个 Tab 之间切换，而非自然对话 |
| **不利用 Agent 能力** | TARS 最强的能力是对话式 Agent，却把它降级为表单填写工具 |

## 一、重新定位

**售前管理不是一个新的"页面"，而是一个融入 Chat 对话的智能工作流。**

```
用户打开 TARS → 开始对话 → AI 引导完成整个售前流程
                                    ↓
                          调研 → 报告 → 方案 → PPT → 归档
```

- 知识库/Wiki 在后台**自动检索、自动归档**，不需要用户手动操作
- 每个阶段产出物直接显示在对话中，可交互修改
- 售前经理只需**说话**，不需要操作界面

---

## 二、触发方式

| 方式 | 用户说什么 | TARS 做什么 |
|------|----------|-----------|
| 命令触发 | `/presales start 项目名` | 启动售前工作流 |
| 自然语言 | "帮我做一个售前方案" | 激活售前技能集 |
| 关键词 | "客户需求"、"技术方案"、"投标" | 自动激活对应阶段技能 |
| 侧边栏 | 点击「售前」快捷入口 | 创建预配置的售前会话 |

## 三、工作流各阶段（7 Steps）

### Stage 1: 项目立项 ← 对话引导

```
AI: 好的，开始一个新的售前项目。请告诉我：
    1. 项目名称是什么？
    2. 客户公司名称？
    3. 所属行业？

用户: 港口数字化项目，深圳港集团，港口物流

AI: 已创建项目「港口数字化项目」。接下来进行需求调研。
    我会分几个阶段提问，每次只问 2-3 个问题。
    准备好了吗？
```

**产物：** 项目记录（存储在 presales_projects 表中）

### Stage 2: 需求调研 ← 结构化问卷

按照行业规范（参考洋山四期需求说明书格式），分 4 个子阶段：

```
子阶段 A: 背景了解（3 个问题）
  Q1: 项目发起的业务背景是什么？
  Q2: 期望达成的核心目标？
  Q3: 当前存在的主要痛点？

子阶段 B: 功能需求深挖（逐领域）
  Q: 在 [数据可视化/调度管理/设备监控/...] 方面有什么具体需求？
  
子阶段 C: 非功能需求
  Q: 对系统性能（并发、响应时间）、安全性、可用性有什么要求？

子阶段 D: 约束条件
  Q: 预算范围？时间要求？技术栈偏好？
```

**每轮对话 AI 做三件事：**
1. 提 2-3 个具体问题
2. 总结已收集的信息
3. 标记信息完整度（xx% 完成）

**产物：** 实时更新的需求草稿（`requirement_summary` 字段）

### Stage 3: 需求调研报告 ← AI 生成

```
用户: 需求收集差不多了，生成调研报告吧

AI: 好的。根据已收集的信息，生成以下报告：

━━━━━━━━━━━━━━━━━━━━━━
  深圳港集团港口数字化项目 — 需求调研报告

  1. 项目背景
     深圳港集团...（AI 填充）

  2. 需求清单
     | 编号 | 需求项 | 优先级 | 来源 |
     |------|--------|--------|------|
     | REQ-001 | 全局数字孪生可视化 | Must | 客户明确 |
     | REQ-002 | 船舶调度优化 | Must | 客户明确 |
     | ...

  3. 约束条件
     预算: xxx 万 / 周期: 6个月 / 技术栈: ...

  4. 待确认事项
     - [ ] xx 功能的具体范围
     - [ ] 第三方系统集成方案

  需要修改哪些内容？
━━━━━━━━━━━━━━━━━━━━━━
```

**报告结构参考标准：**（综合洋山四期需求说明书 + 深圳港信息收集报告）

| 章节 | 内容 |
|------|------|
| 1. 文档控制 | 版本、日期、编制人 |
| 2. 项目背景 | 客户概况、业务痛点和目标 |
| 3. 需求清单 | 编号 + 需求项 + 优先级(Must/Should/Could/Won't) + 确认状态 |
| 4. 用例/场景 | 核心业务场景描述 |
| 5. 非功能需求 | 性能、安全、可用性、可维护性 |
| 6. 约束与假设 | 预算、周期、技术约束、依赖假设 |
| 7. 术语表 | 项目特有术语解释 |
| 8. 待确认项 | 需进一步明确的事项 |

### Stage 4: 方案匹配 ← AI 检索

```
AI: 正在从知识库中检索与「港口数字化」相关的历史方案...
    
    找到 3 个相关方案：
    
    1. 外四外五数字孪生项目建议书（匹配度 85%）
       - 可复用：技术架构章节、数字孪生方案
       - 需调整：业务场景替换为深圳港
    
    2. 山东港口指挥中心方案（匹配度 72%）
       - 可复用：调度中心设计方案
       - 需调整：数据源对接部分
    
    3. 大连DCT二期项目（匹配度 65%）
       - 可复用：堆场管理方案
    
    使用这些参考方案来撰写技术方案吗？
```

**检索源：** TARS 知识库 RAG（自动，不需要用户手动操作）

**方案标准结构（综合行业规范）：**

### Stage 6: PPT 生成

```

    Slide 2: 目录

```


## 四、实现方式

### 4.1 使用 TARS Pipeline 机制

每个售前项目对应一个 Pipeline，7 个阶段对应 7 个 Pipeline Step：

```yaml
# pipelines/presales.yaml
name: presales_workflow
steps:
  - id: project_init
    name: 项目立项
    skill: presales_init
    
  - id: requirement_research
    name: 需求调研
    skill: requirement_analyst
    depends: [project_init]
    
  - id: requirement_report
    name: 需求报告
    skill: requirement_analyst
    depends: [requirement_research]
    
  - id: proposal_match
    name: 方案匹配
    skill: proposal_matcher
    depends: [requirement_report]
    
  - id: proposal_write
    name: 方案撰写
    skill: doc_writer
    depends: [proposal_match]
    
  - id: ppt_generate
    name: PPT 生成
    skill: ppt_outline
    depends: [proposal_write]
    
  - id: archive
    name: 归档
    skill: presales_archive
    depends: [ppt_generate]
```

### 4.2 技能定义（精简化）

只需要 **3 个技能**（已创建）+ 新增 1 个归档技能：

| 技能 | 作用 |
|------|------|
| `requirement_analyst` | 引导调研 + 生成需求报告 |
| `doc_writer` | 生成技术方案 |
| `ppt_outline` | 生成 PPT |
| `presales_archive`（新增）| 自动保存到 Wiki |

**`proposal_matcher` 改为 doc_writer 内部能力**：方案撰写时自动 RAG 检索知识库，不需要单独技能。

### 4.3 前端改动（最小化）

| 改动 | 说明 |
|------|------|
| **保留 /presales 路由** | 但不再是独立页面，而是创建预配置售前会话 → 跳转到 Chat |
| **侧边栏「售前」入口** | 点击后直接打开 Chat，自动发送售前引导消息 |
| **命令支持** | `/presales start` 命令在聊天中启动工作流 |
| **删除独立的 Tab 页面** | 删除 RequirementResearch / ProposalEditor / PPTGenerator / MaterialLibrary |
| **保留 PresalesProjectList** | 作为项目列表（在 Chat 侧边栏或独立抽屉中） |

### 4.4 项目持久化

保留 `presales_projects` 表，但数据由 Pipeline 自动填充：

```
用户在 Chat 中对话
    ↓
Pipeline 自动提取信息存入 DB
    ↓
用户可以在项目列表中查看历史项目
    ↓
点击历史项目 → 恢复对话上下文继续
```

## 六、与 v2.0 的对比

| 维度 | v2.0（独立页面） | v3.0（Chat-First） |
|------|-----------------|-------------------|
| 交互方式 | 填写表单、切换 Tab | 自然对话，AI 引导 |
| 知识库 | 手动浏览、查找 | AI 自动检索、引用 |
| 文档生成 | 点击按钮 → 等结果 | 对话中自然生成 |
| 修改文档 | 编辑 Markdown | 对话中描述 → AI 修改 |
| 学习成本 | 需要学习页面操作 | 零成本（说话即可） |
| 代码量 | ~2000 行前端组件 | ~300 行 Pipeline 配置 |
| 维护成本 | 高（独立 UI 维护） | 低（复用 Chat 组件） |

## 八、默认方案格式与口吻（参考深圳港 ver6.2）

AI 生成所有售前文档时，默认采用以下格式和口吻，参照：

> `/Users/daobanxiang/Desktop/港航/202605深圳/20260601-深圳港集团数字孪生一体化平台建设方案 ver6.2.docx`

### 8.1 文档结构（9 章标准模板）

```
第一章 项目概述与战略定位
  1.1 项目背景（国家政策→城市定位→企业需求三层递进）
  1.2 建设目标与愿景
  1.3 研究范围与边界

第二章 现状分析与需求调研
  2.1 客户业务现状（业务范围/组织架构/数据指标）
  2.2 痛点问题（逐条分析，每条配具体表现）
  2.3 需求分析（按业务域逐项展开）

第三章 总体解决方案（核心）
  3.1 建设范围
  3.2 系统功能建设（按模块分节，每模块3-7级标题深挖）
  3.3 层次化建设（集团级→港区级→码头级）
  3.4 运营管控指标体系（分层分主题）
  3.5 技术架构和部署（引擎/客户端/服务端/组件/大屏/智能体）

第四章 产业资源管控（如适用）
  4.x 按具体产业域展开

第五章 核心业务枢纽（如适用）
  5.x 按具体业务场景展开（事中监控/事后分析/事前推演三阶段）

第六章 智慧监管（如适用）
  6.x 按监管业务域展开（全景/库区/月台/闸口/应急/风险）

第七章 集疏运/物流通道（如适用）
  7.x 按物流通道域展开（基建/监控/预警/分析/仿真/联运）

第八章 配套硬件资源

第九章 项目成本和计划估算
  9.1 分阶段建设成本
  9.2 实施计划与里程碑
```

### 8.2 写作口吻（5 条原则）

| 原则 | 说明 |
|------|------|
| **政策引路** | 每章以国家/省/市级政策文件开篇，再落到具体方案 |
| **数据说话** | 高频使用具体数字（吞吐量、标箱数、泊位数、投资额） |
| **官方语体** | 使用"本项目""平台定位为""面向""支撑""统筹"等正式用词 |
| **三层递进** | 宏观政策→中观企业→微观技术，层层落地 |
| **不空谈** | 每个论断配具体支撑（政策名称+文号、数据来源、场景描述） |

### 8.3 典型段落口吻（示例）

```
深圳港位于粤港澳大湾区核心区域，是深圳建设全球海洋中心城市和
国际性综合交通枢纽城市的重要支撑。作为全球集装箱吞吐量排名第四、
全国第三的国际枢纽海港，2025年深圳港集装箱吞吐量历史性突破3500万
标箱，同比增长超5%，刷新开港以来最高纪录。

在上述政策导向下，本项目建设的数字孪生一体化平台定位为连接港区
实体、生产系统、物流网络、仓储节点、经营管理和决策分析的集团级
综合数字底座。平台通过统一数据标准、统一空间表达、统一指标口径和
统一交互入口，支撑集团实现从分散感知向集中呈现、从单点监控向全域
研判、从经验管理向数据驱动决策转变。
```

### 8.4 文档类型速查

| 文档类型 | 默认格式 |
|---------|---------|
| **需求调研报告** | 第1-2章（背景+现状+痛点+需求） |
| **技术方案** | 第1-9章（完整版） |
| **汇报PPT** | 基于第1/2/3/5/9章精简 |
| **投标响应** | 按招标要求映射到对应章节 |
