# TARS 敏捷开发指南

> 基于 Scrum 和 Kanban 的混合开发流程

---

## 🎯 开发理念

**核心原则**:
1. **迭代式开发**: 每个阶段都是可交付的迭代
2. **测试先行**: 每个功能都要有对应测试
3. **持续反馈**: 每步完成都回顾 DESIGN.md
4. **关联开发**: 模块间相互依赖，不孤岛开发

---

## ✅ 验收清单 (Definition of Done - DoD)

**每个任务完成必须满足**:
- [ ] 代码已编写
- [ ] 单元测试已通过
- [ ] 集成测试已通过 (如适用)
- [ ] DESIGN.md 回顾检查
- [ ] 相关文档已更新
- [ ] 代码格式化/检查已通过

---

## 🔄 每日工作流

```
1. 选择看板上的任务 → Pull to "In Progress"
2. 编写测试用例 (TDD)
3. 实现功能代码
4. 运行测试 (make test)
5. 代码检查 (make lint)
6. 回顾 DESIGN.md 确认符合预期
7. 标记任务到 "Review"
8. 功能完全验收后移到 "Done"
```

---

## 📝 回顾会议 (Retrospective)

**每个阶段完成后**:
1. 回顾哪些做得好
2. 识别可以改进的地方
3. 调整下一阶段计划
4. 更新 DESIGN.md (如需要)
