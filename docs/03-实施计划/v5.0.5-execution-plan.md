## 3. 优先级与依赖

### 批次一内部顺序（建议串行验证，并行开发）
1. **S1 skills 认证** — 独立，最先做（最高可利用风险，改动最小）。
2. **S2 knowledge 清理** — 独立，但牵连 meeting/memory，需回归验证转存功能。
3. **S4 认证审计** — 依赖现有 audit_logger，独立。
4. **S5 密钥** — 独立。
5. **S3 工具沙箱** — 独立，但需充分回归（怕误伤正常 workspace 操作）。
6. **S6 限流+体积** — 独立。

> S1/S4/S5/S6 可并行开发；S2/S3 需更多回归时间，单独验证。

### 跨批次依赖
- **P2 trace_id** 应在 **P1 日志框架**之后（日志要注入 trace_id）。
- **A6 决策追溯** 依赖 **P2 trace_id**（决策记录带 trace_id）。
- **P4 schema 迁移**先建好版本表，后续 A2（审批持久化）、A6（决策表）的建表走迁移框架。
- 其余项相互独立。

## 4. 验证策略

| 层级 | 手段 |
|------|------|
| 编译 | `py_compile` 每个改动文件 |
| 单元 | `pytest tests/` 相关用例 + 新增用例 |
| 导入 | `scripts/check_imports.py`（S2 新增，CI 常驻）|
| 安全 | 手测裸奔端点、沙箱绕过、限流（M1 前必做）|
| 前端 | `vue-tsc --noEmit`（涉及前端改动时）|
| 回归 | 全量 `pytest`，确保不破坏既有 |

每批次合入前：本批全项验证通过 + 全量回归绿。

## 5. 风险登记

| 风险 | 批次 | 缓解 |
|------|------|------|
| S2 删 knowledge 误伤 meeting/memory 转存 | 一 | 保留 wiki 等价路径，转存功能专项回归 |
| S3 沙箱误伤正常 workspace 操作 | 一 | 白名单 allowed_dirs 充分测试，灰度 |
| P1 日志大面积改动引入笔误 | 二 | 按模块分批 PR，每批可独立回滚 |
| P4 迁移脚本损数据 | 二 | 迁移前自动备份 + dry-run + 幂等校验 |
| P6 统一响应破坏前端 | 二 | 全局处理器向后兼容，包装分阶段迁移 |
| 单进程约束被误配多 worker | — | lifespan 加多 worker 检测 fail-fast（A7）|
